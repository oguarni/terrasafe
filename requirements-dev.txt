# untrusted XML read local files) landed in 6.1.0, but lxml is transitive:
# cyclonedx-bom 4.2.0 -> cyclonedx-python-lib[validation] capped it at
# `lxml>=4,<6`, so 6.1.0 was unreachable. Forcing an lxml pin under the old
# cap would have produced a broken resolve; bumping the parent is the fix.
# cyclonedx-bom 7.3.1 requires cyclonedx-python-lib[validation]>=8.0, whose
# cap is `lxml<7`. The `cyclonedx-py requirements` CLI that `make sbom` calls
# is unchanged — verified generating an 18-component CycloneDX 1.6 document.
cyclonedx-bom==7.3.1
# Pinned for the same reason as starlette: a transitive security floor should
# be reproducible, not left to whatever satisfies `lxml<7` on the day.
